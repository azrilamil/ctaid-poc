# Data and privacy

## Summary

This repository contains no clinical data, no personal records, no DICOM images
and no third party photographs. It ships one dataset, and that dataset was
generated by the code in this repository.

## What is in the repository

| Item | Content | Origin |
| --- | --- | --- |
| `data/synthetic_features.csv` | 2100 rows, 68 columns | `scripts/generate_synthetic_data.py` |
| `app/schema.py` | column names, dtypes, value ranges | design brief, ranges only |
| `models/*.joblib` | fitted classifiers | trained on the CSV above, git ignored |
| `app/assets/hero_heart_lungs.svg` | hero illustration | generated by `app/artwork.py` |
| `docs/screenshots/*` | placeholder slots | to be filled with captures of this app |

## What is not in the repository

- Real patient records, identifiers, dates of birth or scan references.
- DICOM or any other image from a scanner.
- Original research tables, original sample CSV files, original trained models.
- Institution names, department names, supervisor names or funder names.
- Credentials: no API keys, no bucket keys, no tokens. Every secret is read
  from the environment at run time.

## Identifiers

The original design used a per-patient identifier. This demo uses `Record ID`
instead: a sequential integer from 1 to 700, regenerated with the dataset. It
does not map to any person, and it changes if the dataset is regenerated with a
different record count.

`app/privacy.py` enforces the column rule: a committed CSV must contain
`Record ID` and must not contain a per person identifier header. The scanner
keeps that forbidden header encoded, so the repository does not spell it out.

## Personal data patterns

The scanner also rejects things that should never appear in a public repository:

- email addresses, except the documented placeholder addresses
- phone numbers
- API keys and tokens (`sk-`, `AKIA`, `ghp_`, private key blocks)

## Upload handling

The Prediction page accepts a small CSV and treats it as untrusted:

1. Extension must be `.csv`.
2. Size must be at most 2 MB.
3. Content type must be text or CSV.
4. The first 4 KB must decode as text with no null bytes.
5. Row count must be at most 500.
6. Identifier and label columns are dropped before scoring.

Accepted uploads are written to the demo object store under `uploads/` and are
cleared by the daily reseed. Uploads are not shared between visitors and are
never used to retrain anything.

## Prediction history

Logged predictions contain only the predicted class, the class probabilities,
the source and a timestamp. No free text, no identifier and no visitor data is
stored. The daily reseed clears the table.

## Content scan

```bash
python scripts/scan_content.py            # writes /tmp/ctaid-poc-scan.txt
```

The scan walks the public work tree and checks for:

- institution and project markers that must never ship
- original data and image file names
- emails, phone numbers, API keys, private key blocks
- identifier headers that would name a person
- em dashes and en dashes in any text file
- Malay leftovers in prose files

Exit code is 0 only when the tree is clean. `tests/test_privacy.py` runs the same
scanner as part of the test suite, so CI fails on a leak.

## Secrets policy

`.env` and `.env.*` are git ignored. `.env.example` documents the variable names
with empty values. The application never logs a secret, and the storage and
backend clients read credentials from the environment only.

## Limits of this demo

This is a portfolio demonstration of engineering, not a research result. The
data is fake, the metrics describe fake data, and no clinical claim of any kind
is made or implied.
