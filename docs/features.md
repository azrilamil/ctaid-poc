# Features by page

The app has four pages behind a sidebar, matching the information architecture
of the original research tool: Home, Data Exploration, Model Training,
Prediction. The demo notice sits on every page.

## Home

- Hero band with an original generated SVG (lungs, heart, vessel trace, scan
  rings). Generated by `app/artwork.py`, no third party image.
- Title line with the full expansion of CTAID-A and a short lede.
- Four stat cards: synthetic rows, feature columns, pattern classes, models.
- Four cards that preview the other pages.
- Class balance bar chart with the four pattern groups.
- Privacy block: what is in the repository, what is not, and how the optional
  cloud wiring degrades to local storage.
- Footer credit and the long demo disclaimer.

## Data Exploration

- Class filter that scopes every chart and table below it. The target column is
  labelled `Pattern` everywhere; the CSV keeps its internal column name behind a
  display alias in `app/schema.py`.
- Stat strip: rows in view, records, feature columns, largest class.
- **Table** tab: sortable view with a row limit, plus a download button for the
  filtered slice.
- **Statistics** tab: a summary card for one feature plus the full descriptive
  statistics table with count, mean, standard deviation, min, median and max.
- **Distributions** tab: overlaid histogram per class with a bin control, next
  to a per class box plot.
- **Relationships** tab: scatter of any two features, coloured by class, capped
  at 900 points with WebGL for speed.
- **Correlations** tab: Pearson or Spearman, strongest absolute pairs as a bar
  chart, and the full heatmap for the top 24 features in an expander.

## Model Training

- Backend status strip: metadata backend, model versions, predictions logged,
  artifact store. With local fallbacks the two storage cards read `Demo storage`
  with the hint `Local to this demo, resets on a schedule`; the raw backend name
  is never shown. Convex and Garage S3 are named only when actually configured.
- Model picker over four classifiers: Logistic Regression, Random Forest, SVM
  (sigmoid calibrated), Gradient Boosting.
- Test split slider, random seed and a row cap for fast demo runs.
- Training really runs: `sklearn` fits on the synthetic table, then artifacts
  are written to `models/` and pushed to the object store.
- Metric comparison table and grouped bar chart for accuracy, macro precision,
  macro recall, macro F1 and macro ROC AUC.
- Per model tabs with the five metrics, the classification report, the confusion
  matrix, one versus rest ROC curves and feature importance.
- Version log: recent model versions with accuracy, ROC AUC, row count and time.

## Prediction

- Model picker: this session's fitted pipelines first, then saved artifacts. It
  opens on the best saved Random Forest (ranked by held out ROC AUC, then
  accuracy), because that is the strongest documented model (accuracy 0.8419,
  macro ROC AUC 0.9595). Saved options quote their scores in the label.
- Three input methods:
  - **Form**: sliders and number inputs for the seven most informative features;
    every other column stays at its synthetic median.
  - **Generated sample**: pick a pattern class and a draw seed, get a row from
    the synthetic table. Never an original sample file.
  - **Upload CSV**: validated for extension, size, content type, binary content
    and row count, then aligned against the trained feature list.
- Result panel: predicted pattern, confidence, model, rows scored, class
  probability bars and the model's top weighted features. Weights are the fitted
  `feature_importances_` for tree models and absolute mean coefficients for
  linear models, so the table is never all zeros.
- Optional logging of the prediction to demo history.
- The medical disclaimer renders again at the bottom of the page.

## Guard rails on every page

- "Demo with synthetic data, not a medical tool." in the page header, in the
  sidebar and in the footer.
- No institution names, no personal names other than the project credit, no real
  records, no clinical claims.
- Counts and metrics are always computed live from the CSV or the fitted model.
